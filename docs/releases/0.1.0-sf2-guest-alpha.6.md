# Syphon Filter 2 PC - Guest Runtime Alpha 6

This experimental Windows x64 build runs retail *Syphon Filter 2* gameplay
through the native PC runtime. It contains no game image or extracted retail
assets.

> Experimental playtester candidate. Mission 1's complete parachute opening
> and Mission 3's dialogue lifecycle now pass interactively. The rebuilt
> checkpoint-audio boundary also passes an interactive death/reload test.
> Mission 7 has been completed with continuous music and healthy audio queues.

## Installation

1. Extract the complete ZIP into a new writable directory.
2. Keep every BIN track beside its corresponding CUE file.
3. Open PowerShell in the extracted directory.
4. Create the required empty developer marker:

   ```powershell
   New-Item -ItemType File -Path .\syphon_filter_cheats
   ```

5. Launch a standalone mission test, replacing `N` and the example path:

   ```powershell
   .\syphon_filter.exe `
     --no-launcher --mission=N --scene-test `
     "D:\PS1\Syphon Filter 2 (USA) (Disc 1).cue"
   ```

Missions 1-8 use Disc 1; Missions 9-21 use Disc 2. The graphical launcher
still targets the SF1 product path and does not expose SF2.

For connected campaign progression, omit `--scene-test`. Keep both disc dumps
in one directory with `Disc 1` and `Disc 2` in their CUE filenames so the host
can resolve the campaign seam automatically.

## Alpha 6 candidate changes

- Connected campaign flow now follows the observed retail order: current
  mission ending movie, save prompt, next mission opening movie,
  briefing/loading, in-engine opening, and gameplay. The Mission 8-to-9 disc
  seam has passed interactively through `9_2.STR`, save, automatic Disc 2
  selection, `10_1.STR`, and Pharcom Expo Center gameplay.
- SF2 save/load screens use the sequel mission catalog instead of leaking SF1
  names. The non-linear Disc 2 runtime-resource order is translated separately
  from player-facing campaign, movie, and save indices.
- AIRBASE's authored mid-mission movie has passed an interactive entry/return
  test. AIRBASEX's `6_3.STR` remains owned by its script action; the duplicate
  terminal host selection was removed and deterministic request/completion
  coverage passes.
- XA admission, host callback, SPU voice, libsound sequence, PCM loudness and
  timeline diagnostics are bounded and available through
  `SF_AUDIO_DIAGNOSTICS=1`. They do not enter save states or alter guest audio.
- Colorado Mountains no longer synthesizes Cross in its loading dispatcher.
  The candidate bridge uses retail's loading-ready state while leaving PAD
  neutral so the unusually early in-engine parachute scene is not skipped.
- Standalone STR skip teardown is idempotent. This removes a duplicate OpenAL
  reset observed immediately before a native skip-time crash. An automated
  Mission 3 skip now reaches guest gameplay and exits cleanly.
- Retail gameplay speech uses absolute ISO LBAs stored in the
  `SCENES1.XA`/`SCENES2.XA` archive handle. The runtime now disables its
  mission-relative FOG namespace while XA owns the drive instead of adding the
  archive base a second time. Mission 1's complete parachute introduction and
  Mission 3's conversations now play the correct voices, end naturally, and
  hand control back at the authored points.
- Retail checkpoint restore is treated as an audio-generation boundary. PCM
  produced while the synchronous loader has suspended the sound callback is
  discarded instead of being queued ahead of resumed gunshots and effects;
  post-reload synchronization passes interactively.
- A continuous gameplay-audio backlog now performs a bounded faded resync
  instead of terminating with `Gameplay audio timeline exceeded its FIFO
  bound`. Callback starvation waits for a small recovery cushion before
  resuming, reducing repeated silence and popping after an underrun.
- Controllers connected before launch are attached when LIBPAD registers its
  pad buffer instead of depending on a later SDL hot-plug event. Physical pad
  and keyboard/mouse inputs remain simultaneous. Physical face buttons no
  longer also populate SF2's derived face-axis fields, preventing crouch/back
  and roll/turn compound actions. Movement, actions and the corrected face
  buttons passed an interactive Xbox-controller playtest.
- SF2 interrupt callbacks now use reserved low RAM below the retail
  executable. The previous synthetic stack address mirrored physical RAM used
  by large checkpoint CD transfers; Mission 15 could overwrite its saved
  return address during death/reload. Mission 15 and the remaining Disc 2
  combat/restart routes now pass 4,000-frame validation.

## Known limitations

- Quick states are in-session only and do not persist after process exit.
- The SF2 path remains command-line only; the launcher still targets SF1.
- Missions other than the interactively completed subset still require full
  human playthrough coverage despite deterministic route validation.

## Reporting issues

Include the mission number, approximate location, actions immediately before
the problem, last dialogue line, screenshots, and the log generated beside the
executable. Never upload BIN/CUE files or other copyrighted game data.
