# Syphon Filter 2 PC - Guest Runtime Alpha 11

This is the release note for the experimental Windows x64 Alpha 11 playtest
build. Save and Quit, checkpoint-free parachute restarts and Mission 6's NVG
presentation have passed interactive checks. Restart Mission and consecutive
Missions 8-21/ending coverage remain open playtest gates. The package contains
no game image or extracted retail assets.

## Installation

1. Extract the complete ZIP into a new writable directory.
2. Keep every BIN track beside its corresponding CUE file.
3. Open PowerShell in the extracted directory.
4. Create the required empty developer marker:

   ```powershell
   New-Item -ItemType File -Path .\syphon_filter_cheats
   ```

5. Launch a standalone mission, replacing `N` and the example path:

   ```powershell
   .\syphon_filter.exe `
     --no-launcher --mission=N --scene-test `
     "D:\PS1\Syphon Filter 2 (USA) (Disc 1).cue"
   ```

Missions 1-8 use Disc 1; Missions 9-21 use Disc 2. For connected campaign
progression, omit `--scene-test` and keep both disc dumps in one directory with
`Disc 1` and `Disc 2` in their CUE filenames. The graphical launcher still
targets Syphon Filter 1 and does not expose SF2.

## Candidate changes since Alpha 10

- Device waits use bounded repeated-execution detection and guest-cycle
  hardware scheduling rather than executable addresses, polled API identity,
  or display-bound time. Ordinary presentation cadence remains exact.
- Mission 1 and Mission 8 remain checkpoint-free through their authored
  parachute starts until retail itself serializes a checkpoint. Failure while
  absent reconstructs the active mission; direct-control missions retain the
  replaced frontend's structurally validated initial capture. This resolves
  [issue #2](https://github.com/Alexbeav/SF-pc-port/issues/2).
- Checkpoint-free openings now follow the retail opening-transfer event
  families rather than a mission list: `0x72` transfers parachute ownership
  and `0x62` starts opening vehicle/actor sequences. Mission 6 therefore
  rebuilds a fresh guest generation after an early death or Restart Mission,
  allowing its one-shot helicopter/troop flyby to run again instead of
  resuming with consumed opening state.
- Retail MENU's Restart Mission and Save and Quit callbacks now yield at their
  authored package/title boundaries. Save and Quit enters the native durable
  slot picker instead of waiting in an absent retail frontend lifecycle. The
  centered picker, durable save, return to TITLE and subsequent load are
  confirmed interactively.
- Widescreen expansion now covers authored full-frame NVG/color filters,
  fades, scopes, and animated cinematic mattes without effect-specific rules.
- H11 and silenced-sniper preflights now require their distinct retail
  line-based and sprite-heavy optic compositions instead of accepting any
  stable aimed frame. These weapon optics are separate from Mission 6's
  scripted full-screen night-vision filter, which remains an interactive gate.
- F5/F9 validation includes retail display pages and complete GPU presentation
  packets, preventing stale or doubled native presentation from passing.
- The strengthened two-disc matrix distinguishes positive, complete ordinary
  checkpoints from authored opening deferral and adds clean-restart plus
  Mission 6 fresh-generation/replayed-opening gates.
- Direct `--scene-test` launches now consume the retail clean-restart handoff
  and reconstruct the active mission in-process. Previously the guest yielded
  correctly after an early checkpoint-free death, but the one-shot scene host
  closed normally, which looked like a restart crash to direct-mission users.
- All 21 forced success-shell routes pass without injecting the completed
  mission's synthetic player inventory into the next retail package. Durable
  saves retain their exact sequel block, while destination gameplay starts
  from its authored character, vitals and loadout.
- The exact post-restart candidate passes 21/21 completion flows, 21/21
  quick-state routes, and 21/21 combat routes. Five opening-transfer packages
  independently replay their authored event in fresh guest generations. The
  first full attempt intentionally remains archived: it rejected the initial
  over-broad deferral policy at Mission 2 instead of allowing it to ship.
- The real-disc SF1 compatibility probe and all 21 configured CTests pass.
- Enhanced chase pitch remains dormant across the authored-camera handoff
  until actual mouse-Y input, preventing the camera from snapping upward when
  player control begins.

## Remaining release gates

- Confirm Restart Mission rebuilds the current package while Restart At Last
  Checkpoint remains the distinct retail-owned path.
- Confirm Mission 6 replays the helicopter/troop flyby after an early death,
  Restart Mission, and Restart At Last Checkpoint before a real checkpoint.
- Retain Mission 6 NVG, representative scopes/fades, and cinematic mattes as
  widescreen regression checks; NVG itself is confirmed correct.
- Record consecutive interactive coverage for Missions 8-21 and the connected
  campaign ending.

Quick states remain in-session only. Briefing text and basic frame geometry
render, but the native fallback does not reproduce the retail state-8 frame's
animated mottled surface and can allow grid lines to pierce its border. This is
a known presentation defect, not omitted distributed artwork; the intended
future fix is retail-owned state-8 GPU presentation. Report issues with the
mission number, location, preceding actions, screenshots and generated log.
Never upload BIN/CUE files or other copyrighted game data.

Save and Quit currently persists the active mission cursor through the native
durable slot file. It does not yet serialize retail's in-mission checkpoint
command stream to disk, so loading that slot re-enters the mission rather than
promising the menu's original "last checkpoint" resume semantics. This is a
known alpha limitation, not a completed retail memory-card implementation.

The native title shell currently sends New Game directly into the supported
one-player campaign. Retail's intermediate One Player / Two Players menu and
two-player arena mode are not hosted in this build. Direct SF2 startup uses
Normal difficulty; a retail difficulty selector is not exposed yet.
